# homebrew-tap

Homebrew tap for [CaptainCode](https://github.com/john-nash-rs/captaincode).

```sh
brew tap john-nash-rs/tap
brew install captaincode
```

Or without tapping first:

```sh
brew install john-nash-rs/tap/captaincode
```

## What lives here

| Path | Purpose |
|---|---|
| `Casks/captaincode.rb` | Generated by GoReleaser on each release. **Do not edit by hand.** |
| `README.md` | This file |

The cask is a cask rather than a formula because CaptainCode ships a
prebuilt executable in a tarball, not a package built from source. GoReleaser
deprecated formula generation for this case in v2.16.

## First-time setup

This repository must exist before GoReleaser can push a cask to it. Create it
once:

```sh
gh repo create john-nash-rs/homebrew-tap \
  --public \
  --description "Homebrew tap for CaptainCode" \
  --clone
cd homebrew-tap
mkdir -p Casks
```

Commit at least one file so the repository has a `main` branch:

```sh
touch README.md
git add README.md
git commit -m "Initialise tap"
git push -u origin main
```

## Token

Publishing the cask requires a token that can write to **this** repository.
GitHub's automatic `GITHUB_TOKEN` is scoped to the repository running the
workflow and cannot push to another one.

Create a fine-grained personal access token:

- **Permissions → Repository access:** select only `homebrew-tap`
- **Permissions → Contents:** Read and write
- No other permissions, no other repositories

Then add it as a repository secret on **captaincode**, not on the tap:

```sh
gh secret set GITHUB_PERSONAL_AUTH_TOKEN --repo john-nash-rs/captaincode
```

Without this secret, releases still publish normally — only the cask update is
skipped, and the workflow prints the path to the generated file so it can be
copied manually.

## Sandbox dependency

The cask deliberately declares **no** `depends_on`.

- **macOS** uses `/usr/bin/sandbox-exec`, which ships with the operating
  system. There is nothing to install.
- **Linux** requires `bubblewrap`, which Homebrew on macOS cannot install or
  guarantee. Linux users install it through their own package manager:

  ```sh
  sudo apt-get install bubblewrap
  ```

CaptainCode refuses to execute tools without its sandbox rather than falling
back to running them unsandboxed. `captaincode doctor` reports which backend is
available.

## Verifying a tap change

```sh
brew tap john-nash-rs/tap
brew install --build-from-source john-nash-rs/tap/captaincode  # confirm it builds
brew reinstall john-nash-rs/tap/captaincode
captaincode version
captaincode doctor
```

## Updating manually

If a release published without the token, copy the generated cask:

```sh
cp /path/to/captaincode/dist/homebrew/Casks/captaincode.rb Casks/
git commit -am "Update cask to vX.Y.Z"
git push
```
